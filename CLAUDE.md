# Дневник калорий — как работать с этим репозиторием

## Синхронизация с Google-таблицей (основной сценарий)

Источник данных — таблица «Дневник_питания_2026»
(fileId `1q2yRZvsqzdPcOEzDfo8FsmwuFudK7H1tvhhF8QDxZV4`, владелец пользователя).
Пользователь заполняет её сам: листы месяцев, по 4 приёма пищи на день,
колонки Ккал/Б/Ж/У считаются формулами внутри таблицы.

**Делай ровно эти четыре шага и ничего сверх.**

1. Выгрузи книгу целиком:
   `mcp__Google_Drive__download_file_content` с
   `fileId: 1q2yRZvsqzdPcOEzDfo8FsmwuFudK7H1tvhhF8QDxZV4` и
   `exportMimeType: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.
   Результат слишком большой для контекста, поэтому инструмент сохранит его в файл
   и вернёт путь. **Этот файл читать не нужно** — просто возьми путь.
2. `python3 scripts/import-sheet.py <путь-из-шага-1>`
   Скрипт сам разберёт книгу, обновит `data/days/*.json`, подтянет базу продуктов
   и напечатает шесть строк отчёта. Последняя строка — `ИТОГ: есть изменения`
   или `ИТОГ: без изменений`.
3. Если `без изменений` — **остановись здесь**. Ничего не пересобирай, не публикуй,
   не пиши пользователю. Тихо заверши.
4. Если `есть изменения`:
   `node scripts/build.mjs`, затем опубликуй `app/index.html` инструментом Artifact
   с `url: https://claude.ai/code/artifact/c853ea09-1f09-4769-ad7a-400da968c369`
   (перед публикацией прочитай текущую версию через `action: "read"` с тем же url
   и наложи изменения на неё). Закоммить и запушь в ветку
   `claude/trusting-franklin-bxw19o`.

### Чего не делать

- **Не вызывай `mcp__Google_Drive__read_file_content` для этой таблицы.** Он отдаёт
  ~240 000 символов и при этом обрезает каждый месяц на 15-м дне — данные за вторую
  половину месяца просто теряются. Только xlsx-выгрузка из шага 1.
- Не читай сохранённый base64 и не разбирай XML вручную — для этого есть скрипт.
- Не пересказывай пользователю содержимое таблицы построчно.

## Структура

```
data/foods.json            база продуктов (на 100 г); src:"sheet" — пришло из таблицы
data/profile.json          параметры, режимы тренировок и этапы с нормами
data/days/ГГГГ-ММ-ДД.json  день дневника
data/sheet-state.json      хеши импортированных дней, чтобы видеть только изменения
app/template.html          вёрстка (правится здесь)
app/index.html             собранная страница (правится только сборкой)
scripts/build.mjs          data/ + template → index.html
scripts/import-sheet.py    Google-таблица → data/days/ и data/foods.json
```

`app/index.html` руками не редактируй — он перезаписывается сборкой.

## Позиции в дне

Два вида, оба рабочие:

```json
{ "id": "egg", "pieces": 4 }                                  // ссылка на data/foods.json
{ "name": "Яйцо куриное", "g": 250, "k": 387.5,               // из таблицы, со своими цифрами
  "p": 31.5, "f": 26.5, "c": 2.8 }
```

Импортёр пишет второй вид: цифры уже посчитаны формулами таблицы, так что
сверять их с базой не нужно и незачем.

## Нормы

Считаются в `data/profile.json`, меняются двумя переключателями на странице:
режим тренировок (кардио / силовой) и этап внутри режима. Менять нормы — значит
править `profile.json`, а не вёрстку.
