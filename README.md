# Дневник калорий

Личный трекер калорий и БЖУ. Данные лежат в репозитории обычным JSON, страница-дашборд
собирается из них одной командой.

## Как устроено

```
data/foods.json        база продуктов — всё на 100 г
data/profile.json      параметры тела, цели и нормы БЖУ
data/days/ГГГГ-ММ-ДД.json   один файл = один день
app/template.html      вёрстка дашборда
app/index.html         собранная страница (её и публикуем артефактом)
scripts/build.mjs      сборка: данные + шаблон → index.html
```

## Синхронизация с Google-таблицей

Основной источник данных — таблица «Дневник_питания_2026» в Google Drive.
Порядок описан в `CLAUDE.md`; коротко:

```
# 1. выгрузить книгу в xlsx через Google Drive MCP (результат сохранится в файл)
# 2. разобрать и обновить data/
python3 scripts/import-sheet.py <путь-к-выгрузке>
# 3. если скрипт сказал «есть изменения» — пересобрать и опубликовать
node scripts/build.mjs
```

Импортёр держит хеши дней в `data/sheet-state.json` и печатает только разницу,
поэтому обычный прогон без новых записей стоит шесть строк вывода.

## Рабочий процесс

1. Говоришь: «посчитай завтрак — 4 яйца, 50 г сыра, чай с 20 г сахара».
2. Продукты ищутся в `data/foods.json`; чего нет — добавляется туда же.
3. Приём пищи дописывается в файл дня в `data/days/`.
4. `node scripts/build.mjs` пересобирает `app/index.html`.
5. Артефакт переиздаётся по той же ссылке.

## Формат дня

```json
{
  "date": "2026-09-10",
  "weightKg": 89.7,
  "meals": [
    { "name": "Завтрак", "time": "08:20", "items": [
      { "id": "egg", "pieces": 4 },
      { "id": "cheese45", "g": 50 }
    ]}
  ]
}
```

`pieces` — если продукт удобнее считать штуками (в базе задан вес одной штуки),
`g` — если граммами. Сборка падает с ошибкой, если в дне встретился `id`, которого нет в базе.

## Формат продукта

```json
{ "id": "egg", "name": "Яйцо куриное", "cat": "Белковое",
  "per100": { "k": 157, "p": 12.7, "f": 11.5, "c": 0.7 },
  "piece": { "label": "шт", "g": 57 } }
```

`k` — ккал, `p` — белки, `f` — жиры, `c` — углеводы, всё на 100 г. `piece` может быть `null`.

## Нормы

Считаются в `data/profile.json`. Там два уровня переключателей, оба живут на странице:

- **Режим тренировок** — `modes`: кардио (кардио + работа с собственным весом) и силовой
  (со снарядами). У каждого свой набор этапов: в кардио-режиме дефицит глубже и белок выше,
  в силовом — мягче дефицит и заметно больше углеводов.
- **Этап** — `phases` внутри режима: похудение, тот же этап на меньшем весе, мягкий дефицит,
  поддержание, целевой вес.

- **Калории** — формула Миффлина — Сан Жеора → расход за сутки (×коэффициент активности)
  → минус дефицит этапа. Дефицит задан от целевого темпа: 300 г жира в неделю ×
  7 700 ккал/кг ÷ 7 = −330 ккал в день.
- **Белки** — 2.4 г на кг сухой массы (1.9 г на кг веса): Helms и соавторы дают
  2.3–3.1 г/кг сухой массы для сохранения мышц в дефиците.
- **Жиры** — 0.9 г на кг веса тела, не ниже 0.6–0.8 г/кг.
- **Углеводы** — остаток калорийного бюджета.
- **Активные калории** — если в дне есть поле `activeKcal`, они показываются отдельной
  карточкой и к норме автоматически не прибавляются: базовая активность уже учтена
  в коэффициенте.
